# Документация микросервиса аутентификации и авторизации: auth_service

## Данные
- `id` (Long): Первичный ключ (Primary Key), генерируется базой данных автоматически.
- `email` (String): Обязательное поле, должно быть уникальным, содержит валидный адрес электронной почты пользователя.
- `password` (String): Обязательное поле, хранится исключительно в виде криптографического хеша.
- `role` (String): Обязательное поле, определяющее уровень доступа пользователя.

## Пользовательские роли
- **USER:** Обычный клиент маркетплейса. Авторизуется для получения возможности оформлять заказы (`order_service`) и взаимодействовать с каталогом товаров.
- **ADMIN:** Администратор системы. Обладает расширенным доступом для управления каталогом (`catalog_service`), модерации контента и контроля заказов.

## API
- **POST /api/auth/register**
  * Описание: Регистрация нового пользователя в системе.
  * Тело запроса (JSON): `email`, `password`.
  * Возвращает: Статус `200 OK` / `201 Created` и сгенерированный JWT-токен (алгоритм HS256) для передачи в API Gateway.
- **POST /api/auth/login** *(планируемый эндпоинт)*
  * Описание: Вход существующего пользователя.
  * Тело запроса (JSON): `email`, `password`.
  * Возвращает: Статус `200 OK` и актуальный JWT-токен авторизации.

## Технологии разработки
**Язык программирования:** 
- Java 21 .
- Основной фреймворк: Spring Boot 3.3.4 (модули Spring Security, Spring Data JPA, Spring Web).
- Генерация токенов: библиотека JJWT.

**СУБД:** 
- PostgreSQL 16 (работает в изолированном Docker-контейнере).
- Взаимодействие с БД реализуется через Hibernate.

## Тестирование
