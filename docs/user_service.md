# Документация микросервиса управления профилями: user_service

## Данные
- `id` (Long): Первичный ключ (Primary Key), генерируется базой данных автоматически.
- `auth_id` (Long): Обязательное поле, уникальный идентификатор учетной записи из `auth_service` (для связи аутентификации и профиля).
- `first_name` (String): Имя пользователя.
- `last_name` (String): Фамилия пользователя.
- `phone_number` (String): Контактный номер телефона (уникальное поле, если заполнено).
- `address` (String): Адрес доставки заказов по умолчанию.

## Пользовательские роли
- **USER:** Обычный клиент маркетплейса. Может просматривать и редактировать только свой собственный профиль.
- **ADMIN:** Администратор системы. Обладает доступом к профилям всех пользователей для модерации и клиентской поддержки. Также может изменять каталог.

## API
- **GET /api/users/profile** *(планируемый эндпоинт)*
  * Описание: Получение данных профиля текущего авторизованного пользователя.
  * Тело запроса: пустое (идентификатор берется из HTTP-заголовка, прокинутого API Gateway).
  * Возвращает: Статус `200 OK` и JSON-объект с данными профиля.
- **PUT /api/users/profile** *(планируемый эндпоинт)*
  * Описание: Создание или обновление личных данных пользователя.
  * Тело запроса (JSON): `first_name`, `last_name`, `phone_number`, `address`.
  * Возвращает: Статус `200 OK` и обновленные данные.

## Технологии разработки
**Язык программирования:** 
- Java 21 .
- Основной фреймворк: Spring Boot 3.3.4 (модули Spring Data JPA, Spring Web).
- Безопасность: доверенное взаимодействие внутри сети Docker (чтение ID пользователя из заголовков от API Gateway).

**СУБД:** 
- PostgreSQL 16 (работает в изолированном Docker-контейнере, отдельная база `user_db`).
- Взаимодействие с БД реализуется через Hibernate (ORM) и пул соединений HikariCP.
