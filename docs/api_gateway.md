# Документация API-шлюза: api_gateway

## Данные
- `jwt_token` (String): Извлекается из заголовка `Authorization`. Шлюз проверяет его криптографическую подпись (алгоритм HS256) и срок действия, не обращаясь к базе данных (возможно использование Redis для blacklist).
- `routes` (Configuration): Внутренние правила маршрутизации, определяющие, на какой микросервис перенаправить запрос.

## Пользовательские роли
- **UNAUTHENTICATED (Анонимный):** Имеет доступ только к открытым эндпоинтам (например, маршрутизация на `/api/auth/register` и `/api/auth/login`).
- **USER / ADMIN:** Получают доступ к защищенным внутренним сервисам. После проверки токена шлюз извлекает роль и ID, добавляет их в HTTP-заголовки и передает далее микросервисам.

## API
- **ANY /***
  * Описание: Единая точка входа для всего клиентского трафика. Перехватывает запросы, проводит терминацию безопасности (проверку JWT) и маршрутизирует их в целевые микросервисы (`auth_service`, `user_service`, `order_service` и т.п.).
  * Возвращает: Ответ от целевого внутреннего микросервиса, либо ошибку `401 Unauthorized` / `403 Forbidden`, если токен недействителен, отклоняя запрос на границе сети.
