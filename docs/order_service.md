## Описание
- Наименование: Микросервис корзины и заказов для приложения сети кофеен.

- Предметная область: Электронная торговля. Добавление товаров в корзину, сохранение её содержимого и оформление покупки. 
## Данные
1. Таблица `cart_items` (Позиции в корзине)

- id (SERIAL): Первичный ключ.

- user_id (BIGINT): Идентификатор пользователя. Ограничение: NOT NULL.

- product_id (INT): Идентификатор товара (ссылка на логическую сущность в Catalog Service). Ограничение: NOT NULL.

- quantity (INT): Количество товара. Ограничение: CHECK (quantity > 0).

- Составной ключ: UNIQUE (user_id, product_id) - один и тот же товар НЕ дублируется в корзине пользователя отдельными строками

2. Таблица `orders` (Заказы)

- id (SERIAL): Первичный ключ.

- user_id (BIGINT): Идентификатор пользователя. Ограничение: NOT NULL.

- status (VARCHAR): Статус обработки заказа (по умолчанию при создании записывается 'created').

3. Таблица `order_items` (Состав заказа)

- id (SERIAL): Первичный ключ.

- order_id (BIGINT): Внешний ключ. Ограничение: NOT NULL, REFERENCES orders(id) ON DELETE CASCADE.

- product_id (INT): Идентификатор товара. Ограничение: NOT NULL.

- quantity (INT): Количество приобретенного товара. Ограничение: CHECK (quantity > 0).

Общие ограничения целостности:  

• Ссылочная целостность: Реализована через внешние ключи. Правило ON DELETE CASCADE гарантирует, что при удалении заказа автоматически удалятся и все его позиции.

• Транзакционная целостность: Операция чекаута (Checkout) выполняется в единой SQL-транзакции. Копирование товаров из cart_items в order_items и последующая очистка корзины либо выполняются успешно вместе, либо полностью откатываются в случае ошибки.

• Доменная целостность: Использование ограничений CHECK защищает от ввода отрицательного количества товаров.

## Пользовательские роли  
Проверка аутентификации происходит через API Gateway

• авторизованный USER.
- _Ответственность:_ Просмотр личной корзины, добавление товаров, оформление заказа. Клиент имеет доступ только к своей корзине. 
- _Количество:_ Неограниченно.

 Внутренний сервис (Catalog Service).

- _Ответственность:_ Предоставление актуальных данных о стоимости товаров по внутреннему HTTP-запросу, чтобы предотвратить подмену цен пользователями при чекауте.
- _Количество:_ 1-5 экземпляров микросервиса.

## UI / API
Взаимодействие с сервисом реализовано по REST через HTTP/JSON API. UI отсутствует, сервис отдает только данные.
- Защита эндпоинтов: Роуты сгруппированы под /api/v1/ и защищены AuthMiddleware. 
- Основные маршруты API:

- POST /api/v1/cart - Добавление товара

- GET /api/v1/cart - Получение списка товаров в корзине

- POST /api/v1/checkout - Транзакционное оформление заказа
